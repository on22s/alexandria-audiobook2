# OS colour-scheme theme resolution and navbar tokens (#2058)

## Resolution order

`resolveThemeKey(stored, osDark)` in `app/static/js/app-core.js` is the single
policy: a valid stored `alex-theme` choice wins; otherwise the OS
`prefers-color-scheme` picks `night` (dark) or `light`; otherwise `light`. A
stored but invalid value is treated as no choice.

- `applyTheme(key, persist = true)` keeps every existing call (including the
  theme button via `cycleTheme()`) unchanged — an explicit choice still writes
  `localStorage`. Initial and OS-driven applications pass `persist = false`, so
  following the OS never creates a stored override.
- `initTheme()` applies the resolved theme and registers a
  `matchMedia('(prefers-color-scheme: dark)')` change listener. The listener
  re-resolves only while no **valid** choice is stored (it uses the same
  `isKnownTheme()` validator as the resolver, so a corrupt or legacy value
  cannot freeze the theme against the OS); once the user clicks the theme
  button, OS changes are ignored.
- The inline anti-flash snippet in `index.html` mirrors the same resolution
  before first paint so an OS-dark user never sees a white flash. It deliberately
  does not persist. `test_theme_os_resolution.py` asserts the two copies stay in
  step.

The optional "System" cycle entry was **not** added (the issue marks it
optional): the six-step cycle is unchanged, and reverting to OS-following after
an explicit choice requires clearing the stored key.

## Navbar tokens

The hard-coded `#c4dcff` / `#edf4ff` / `#a5b4c8` are gone from `index.html`.
`--nav-link`, `--nav-control` and `--nav-control-border` now drive the navbar
links and theme button. Their values live in
`app/static/css/navbar-theme.css`: the light theme keeps the previous colours,
and the other five themes get palette-matched values (night/super-night blues,
cyberpunk cyan/yellow, bread/leek reuse `--nav-accent`).

## Evidence

- Unit: `python -m unittest tests.test_theme_os_resolution` — 7 tests covering
  resolution order, `matchMedia` guards, the persist flag, the live listener,
  anti-flash parity, and the token/grep criteria.
- E2E: `npm run os-theme` (Puppeteer, CDP-emulated `prefers-color-scheme`, fresh
  browser contexts) — 18 checks, 0 failures (12 state/override assertions plus
  an axe `color-contrast` run on the navbar in each of the six themes). Confirms fresh light → `light`,
  fresh dark → `night`, both with no stored key; live OS switches follow while
  no choice is saved; a real theme-button click stores the choice and stops OS
  following; and all six themes expose a distinct navbar link colour. Raw
  output: `docs/audits/theme-os-2026-11-18-e2e.json`.
- No visual regressions: the full contrast suite was re-run — main 0 violations
  × 6 themes; hover 1,296 controls / 0 failures (min 4.50:1); interaction 60
  surfaces / 0 violations; pixels 100 nodes / min 7.2643; AX tree 78/78 named;
  populated casting modal 36 surfaces / 0 violations.
