# 训练指南

[中文主页](Home-CN.md) · [English](Training-Guide.md)

在 Qwen3-TTS Base 模型上训练 LoRA 适配器，创建你自己的声音。训练好的声音会保持一致的身份，并且仍然遵循表达情绪的演绎指令。

> **从下面经过测量的配方开始，不要用更旧的表。** 学习率 **5e-6 会让声音失控**：2 次测试中 2 次声音停不下来，而 1e-6 的 3 次测试中 3 次都正确停止。训练 loss 看不出这一点——只有生成音频能。证据：[RECIPES.md](../../RECIPES.md) §"Voice adapters"。

## 有效的配方

| 用途 | 设置 | 证据 |
|---|---|---|
| 声音库中的声音（一个旁白） | 6 epochs，学习率 **1e-6**，rank 64，alpha 128，180–200 个片段 | 67 个随附声音就是这样训练的，并通过了停止检查 |
| 评估用声音 | 6 epochs，学习率 **1e-6**，rank 32，alpha 128，200 个片段，seed 1234 | 已发布的英语声音结果背后的那些适配器 |

Training 页的默认值接近这个：5 epochs、学习率 1e-6、batch size 1、rank 32、alpha 128、gradient accumulation 8。

## 概览

Training 页随附内置 LoRA 声音，所以你可以不训练任何东西就使用 LoRA 声音。要自己做：

1. **创建数据集**——带文字稿的声音样本（WAV）。
2. **配置训练**——设置参数。
3. **训练**——作为独立进程运行。它需要独占 GPU，所以应用会先卸载自己的 TTS 模型。
4. **测试**——试听训练出的声音。
5. **分配**——在 Voices 页使用该适配器。

## 创建数据集

有两种方式，另有用于整个声音库的 Voice Lab。

### 方式 1：Dataset Builder（合成声音）

用 VoiceDesign 模型根据文字描述生成样本，并逐个试听。最适合不存在真实录音的声音。点击 Training 页的 **Build New Dataset**，或打开 Dataset 页。见 [Dataset Builder](Dataset-Builder-CN.md)。

好的合成数据集：

- 有 **6–25 个样本**；
- 有**真正的情绪多样性**——只有中性数据会产生平淡、抗拒情绪指令的声音；
- 为声音的身份保留一个**根描述**，用每行的情绪控制演绎（两者会合并进 VoiceDesign 提示词）；
- 包含**简短发声**（"Oh!"、"Hmm."、"Right."），让声音学会在短行上停下；
- 以一段**长而平静的中性段落**结尾，它非常适合作为参考样本；
- 对参考样本使用**固定的 seed**，这样重新生成时说话人嵌入保持稳定。

一个士兵声音的示例行：

| 情绪 | 文本 |
|---|---|
| *（空——中性）* | The patrol route has been secured and all positions are accounted for. |
| 尖锐地下达命令 | Move out! I want that perimeter locked down in sixty seconds! |
| 安静、紧张的警告 | Keep your voice down. There's movement in the treeline, fifty meters out. |
| 疲惫、喘气 | We've been marching for twelve hours. The men need rest or we'll lose them. |
| 苦涩、克制的愤怒 | They sent us in without support. Command knew exactly what they were doing. |
| 温和、安慰 | Easy now, son. You did good out there. We're going to get you home. |

### 方式 2 上传真实录音 ZIP

上传这样的 ZIP：

```
dataset.zip
├── sample_001.wav
├── sample_002.wav
├── ...
├── ref.wav            # the reference audio for the speaker embedding
└── metadata.jsonl     # one JSON object per line
```

`metadata.jsonl`：

```json
{"audio_filepath": "sample_001.wav", "text": "The transcript of this sample.", "ref_audio": "ref.wav"}
{"audio_filepath": "sample_002.wav", "text": "Another transcript.", "ref_audio": "ref.wav"}
```

**音频要求**

- WAV，理想情况是 24 kHz 单声道（其他采样率会自动重采样）。
- 没有背景噪声的干净音频。
- **每个数据集一个说话人。**
- 超过 30 秒的片段会被跳过。

**参考音频**

- 每个样本都使用相同的 `ref_audio`；Qwen3-TTS 自己的文档强烈推荐这样做。
- 它提供说话人嵌入，所以一致的参考会让声音更稳定。
- 如果某行没有 `ref_audio`，训练器会使用数据集文件夹里的 `ref.wav`，然后是第一个训练样本。

**没有 emotion 字段。** 真实录音本身就带有情绪，所以 `metadata.jsonl` 没有 `emotion` 字段——在 Dataset Builder 里，情绪只是*生成*音频时的提示。你的录音仍然需要**情绪多样性**，因为声音是从音频本身学习它的表现范围的（见[情绪范围](#情绪范围)）。

### 方式 3：Voice Lab（整个声音库）

Voice Lab 页把有声书批量变成命名好的 LoRA 声音：Preparer 把有声书与文本对齐，然后依次进行去重、批量训练、画像和命名。见 README 的 [Web interface](../../README.md#web-interface) 一节。

### 数据集在磁盘上的样子

```
lora_datasets/{name}/
├── metadata.jsonl      # {audio_filepath, text} per line
├── ref.wav             # reference audio for the speaker embedding
├── ref_text.txt        # the exact transcript of ref.wav
└── sample_000.wav ...  # the training audio
```

## 训练设置

| 设置 | Training 页默认值 | 作用 |
|---|---|---|
| **Epochs** | 5 | 在整个数据集上的完整轮数；越多声音越固定，但有过拟合风险 |
| **Learning rate** | 1e-6 | 每步权重的移动幅度；**不要用 5e-6**（见上面的警告） |
| **LoRA rank** | 32 | 适配器的容量（见下文） |
| **LoRA alpha** | 128 | 缩放系数；实际强度为 alpha ÷ rank（128/32 = 4×，128/64 = 2×） |
| **Batch size** | 1 | 每步的样本数；保持为 1 |
| **Gradient accumulation** | 8 | 在不增加内存的情况下模拟更大的批 |
| **Language** | English | 编解码器的语言 token——**必须与数据集的语言一致** |

### 选择 rank

| rank | 适配器大小 | 最适合 |
|---|---|---|
| **32** | 约 56 MB | 最多约 60 个样本：学会声音而不记住噪声 |
| **64** | 约 111 MB | 120+ 个样本；随附的声音库声音（180–200 个片段）用 64 |

在约 60 个样本上，上游最好的适配器都用 rank 32；在相同数据上用 rank 64 会得到更大但听起来更差的文件，因为多出的容量记住了训练瑕疵。**经验法则：**除非有 100+ 个样本，否则用 rank 32。如果 loss 看起来不错但声音不对，先降低 rank，再考虑改别的。

## 读懂训练 loss

这些 loss 区间来自上游 Alexandria 在小数据集上的测试。只当作粗略参考——**好的 loss 不能证明好的声音。** 5e-6 的失控在 loss 里看不出来；只有试听或停止检查才能发现。

| loss | 音频 | 遵循指令 | 判定 |
|---|---|---|---|
| 4.4 及以上 | 清晰 | 微弱 | 训练不足 |
| 4.1–4.2 | 清晰、有表现力 | 良好 | 最佳区间 |
| 3.9–4.1 | 有表现力，可能含混 | 强 | 临界——每次运行会不同 |
| 3.4–3.8 | 含混但可听懂 | 强 | 过拟合 |
| 3.0–3.3 | 含混，或停不下来 | — | 过拟合，不可用 |

- **数据越多，需要的 epoch 越少**：每个 epoch 教的东西更多。
- 上游发现**总曝光量**（样本数 × epoch）约 250–400 有效；超过 600 有过拟合风险。
- 相同设置在不同运行之间可能落在 4.1 的两侧。

## 训练

1. 点击 Training 页的 **Start Training**。
2. 应用卸载自己的 TTS 模型以释放 GPU。
3. 训练作为独立进程运行，并有实时日志：epoch、loss、学习率和剩余时间。
4. 保留最好的检查点（最低 loss）。
5. TTS 模型会在下次渲染时重新加载。

小数据集几分钟就能训练完。作为参考，在 RX 9070 XT 上重训一个声音库声音（200 个片段）约需 5.4 分钟。

### 训练如何工作

训练器遵循 Qwen3-TTS 官方微调方法：

- **子 loss 加权：**code-predictor loss 的权重为 0.3×，与官方 `sft_12hz.py` 一致。
- **说话人嵌入：**取自一段一致的参考片段，而不是每个样本。
- **训练期间不使用指令：**声音只从音频和文本学习；指令在生成时使用。
- **LoRA 目标：**talker 的注意力层（`q_proj`、`k_proj`、`v_proj`、`o_proj`），通过 PEFT。

## 测试与采纳声音

1. 适配器出现在 Training 页的 **Trained Models** 下。
2. 点击 **Generate**，用你自己的文本和指令测试它。
3. 对比和**盲评**视图让你在不知道哪个是哪个的情况下与当前声音对比试听。采纳会保留旧版本并带一个回执，以便回滚。
4. 如果满意，在 Voices 页把适配器分配给某个角色。

采纳前会运行**停止检查**（身份门），它会发现停不下来的声音。

## 让声音更好的提示

### 情绪范围

有表现力的声音最重要的因素是**训练数据里的情绪多样性**。要包含：

- 中性旁白；
- 高兴或兴奋；
- 愤怒或沮丧；
- 悲伤或低沉；
- 低语或紧张；
- 喊叫或命令。

只有中性的数据会让声音平淡，并抗拒情绪指令。

### 参考样本的指令

生成训练数据时，**不要**给参考样本使用你之后要用的指令（例如 "Neutral, even narration."）。这样训练出的声音倾向于在比参考片段更长的句子上加速、变响。用**空指令**生成参考，节奏更自然。

### 混合片段长度

只用短的单句片段（4–8 秒）训练，会让句与句之间出现音色变化，因为声音从没学会如何从句末过渡到下一句。要包含不同长度：

| 长度 | 内容 | 教会什么 | 数量 |
|---|---|---|---|
| 1–3 秒 | 短感叹（"Oh!"、"Right."、"No!"） | 在短行上停下 | 3–5 |
| 4–8 秒 | 单句，情绪多样 | 核心声音及其范围 | 数据集的大部分 |
| 15–20 秒 | 2–3 句 | 过渡、节奏、流畅 | 5–8 |
| 20–30 秒 | 4–5 句旁白 | 长段演绎 | 2–3 |

### 多少数据

- **最低：**6 个情绪多样的样本。
- **良好：**15–20 个覆盖多种情绪和风格的样本。
- **声音库质量：**随附声音使用 180–200 个片段。
- 上游发现超过 25–30 个合成样本后收益递减，并建议高级声音使用 15–30 分钟音频。

### 真实还是合成？

- **合成（Dataset Builder）：**对情绪控制更好、质量一致、制作快。适合虚构角色。
- **真实录音：**更自然，能捕捉真实声音的细微特质。有干净的单一说话人录音时最好。
- 两者都行。带情绪多样性的合成数据往往比中性的真实录音更有表现力。

## 其他语言

在一种语言上训练的适配器会带上该语言的口音。英语训练的适配器会用英语发音读德语文本——有时可以接受，常常不行。

**为每个说话人的每种语言分别训练适配器**，并把 Training 页的 **Language** 设为数据集的语言（English、Chinese、Korean、Japanese、French、German、Italian、Portuguese、Russian 或 Spanish）。不匹配可能让适配器失去说话人的身份。

## 常见问题

| 问题 | 可能原因 | 修复 |
|---|---|---|
| loss 一直高于 10 | 音频无效或文字稿错误 | 检查 WAV 文件和 `metadata.jsonl` 里的文字稿 |
| 声音停不下来 | 学习率过高，或过拟合 | 用 1e-6 重训；减少 epochs |
| 新文本上音频含混 | 过拟合（loss 太低） | 减少 epochs |
| 音频清晰但不像本人 | 训练不足（loss 太高） | 增加 epochs |
| 平淡、单调的声音 | 数据里没有情绪多样性 | 加入情绪多样的文本对；试更低的 rank（8–16） |
| 听起来不像样本 | 训练不足，或 rank 太低 | 增加 epochs、提高 rank、使用一个一致的 `ref_audio` |
| 语速过快 | 参考样本是带指令生成的 | 用空指令重新生成它 |
| 短行跑到 `max_new_tokens` | 声音没学会在短行上停下 | 在数据里加入短发声 |
| 开头有一点杂音 | clone 提示词对齐 | 很小；整本有声书里通常没有 |
| 参考不匹配 | `ref_text.txt` 与 `ref.wav` 不符 | 让文字稿完全准确 |
| 其他语言里出现错误口音 | 语言设置不匹配 | 把 **Language** 设为与数据一致 |

**不要**为了提高 loss 的表现而提高学习率——先检查数据。
