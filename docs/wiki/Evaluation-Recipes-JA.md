# 評価手順

[日本語ホーム](Home-JA.md) · [English](Evaluation-Recipes.md)

アダプター評価の実施方法です。測定した設定とその根拠は [RECIPES.md](../../RECIPES.md) にあります。

## ペアで比較する構成

リポジトリの評価ツールを使い、**1 つのサーバー**と 2 つのアダプター scale で実行します。

- **base 側：** アダプター scale 0.0。
- **adapter 側：** アダプターが宣言する scale。記録された scale のスイープで別の値を選んでいない限り 1.0 です。

両方の側で次を揃えます。

- temperature 0
- バッチサイズ 25
- 各リクエストの JSON schema
- 同じプロンプトのバリアント

## 報告する内容

- 精度、および未回答の行数とパース失敗の数。
- 本ごとのスコア。
- アダプターのハッシュとベースモデルのハッシュ。
- プロンプトのバリアント。
- 実行環境の詳細（サーバーのビルド、GPU、コンテキスト長）。

## アダプターを昇格してよい条件

- **バッチサイズ 1 のスモークテストだけで昇格しない。** 昇格には、製品が実際に送るウィンドウでの評価と、served-contract preflight の通過が必要です（[Setup と LLM サーバー](Setup-and-Serving-JA.md)参照）。
- **パイロットで 1.0 以外の scale を選んだ場合**は、その scale を全テストセットで繰り返し、試したすべての scale を報告します。scale 1 の失敗を成功と言い換えないでください。
- **テストセットを毎回明記する。** 同じアダプターでも、あるテストセットでは上がり、別のテストセットでは上がらないことがあります（[プロンプトとアダプター](Prompts-and-Adapters-JA.md)参照）。
- **モデルだけでなくスコアラーも確認する。** 2026-09-28 の再スコアリングでは、正しい短い名前が誤って採点されていたため、10 件の判定が変わりました。

## 有料 API のベースライン

ホスト型 API の結果はベースのみの測定なので、アダプター評価とは分けて扱います。

2026-09-22 の Nemotron 3 Ultra 550B A55B の実行は、OpenRouter 経由で `michel2_full`、推論 low、temperature 0、バッチサイズ 8、構造化出力なしで行いました。本ごとのスコアは次のとおりです。

| 本 | 精度 |
|---|---:|
| Mansfield Park | 96.7% |
| Northanger Abbey | 97.6% |
| Persuasion | 97.1% |
| The Sign of the Four | 85.3%（2026-09-28 の再スコアリング後は 96.6%） |
| The Sun Also Rises | 87.3% |

- これらは独立した本の結果です。1 つのモデルスコアにまとめたり、アダプターの効果として読んだりしないでください。
- OpenRouter は要求したモデルを報告しました。ルーティングは Baseten、次に Venice を優先し、フォールバックもありました。プロバイダーのハードウェアは観測していません。
