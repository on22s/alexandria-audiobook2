# TTS capability guidance

Setup → Speech engine describes the selected local or external mode. Changes preview the unsaved selection; generation continues to use saved configuration until Save Configuration. Voice assignments and hidden field values are kept. Unsupported assignments show a warning on Voices; nothing automatically substitutes or saves a voice. Version timelines and ensemble members still undergo native server checks.

The server owns the descriptor and dispatch contract in tts_capabilities.py. Local mode supports custom, clone, LoRA, design and ensemble categories. External mode supports custom and clone voices, and ensembles whose members are supported. Built-in LoRA is described using the same LoRA capability. AA2 returns completed audio files; no incremental streaming or independent speed parameter is promised. External model language support is not inferred.

The read-only descriptor is included in GET /api/config under capabilities.tts_modes. Reading it does not load a model or contact a speech server. Missing or unknown descriptors display unavailable guidance; current settings remain intact and existing server-side refusals remain authoritative.

## Internal render windows (experimental)

Setup → Audio & timing → Internal render windows can split a long saved line into smaller speech calls and assemble one take. The feature is off by default. Enter an explicit character limit for the service and voice category you intend to use, optionally enter a whitespace-word limit, enable it, and Save Configuration. Blank category limits retain existing rendering. Disabling keeps your draft limits. Settings apply to subsequent renders; existing selected takes stay selected.

Limits count the final spoken text after occurrence and shared pronunciation rules. Internal windows preserve that prepared text and do not edit saved lines, source text, speaker assignments or export pauses. Whole words and attached punctuation must fit; an impossible limit fails the render instead of cutting a word or exceeding the limit. Ensembles use the smallest configured limit across the ensemble and its actual members. A line that already fits retains the existing single-call or native batch path.

Blank sentence, clause and paragraph gap targets preserve natural silence. Explicit targets can add missing silence; removing quiet edges also requires a positive trim cap. Fades and continuation crossfades are separately opt-in. The first and last edges of the parent line are retained. Begin with trimming, fades and crossfades at zero, and listen to consonants, breaths, sentence endings and cadence before adopting a policy. AA2 supplies no automatically qualified backend budgets or recommended cadence values.

Each successful split produces one parent take with a `synthesis_receipt` tied to its audio revision: prepared-text hash, exact window spans and audio hashes, policy, and pre-encoding PCM frame/seam accounting. These PCM counts do not describe final MP3 padding. A failed or cancelled parent retains the previous take and discards private working files. In-flight provider calls may finish before cancellation releases ownership.

## Verified window recovery (experimental)

The recovery controls beside internal render windows can retain completed windows across an interrupted render. Recovery is off by default and requires internal windows to split the line. Enable **Keep verified windows for recovery**, choose a retained-audio budget, and Save Configuration. The default limit is 256 MiB, with an allowed range of 16–4096 MiB across the workspace's recovery cache. Disabling preserves retained windows. Changing active recovery settings requires idle tasks and applies to subsequent renders; it does not invalidate selected audio or change voice/acoustic identities.

The initial supported path is an owned, native local CustomVoice, clone or LoRA render on Linux with an actual fixed nonnegative seed, codec compilation disabled, and a known local Qwen model/adapter/reference and runtime. Single, parallel and split native-batch parents use the same verification path. Random seeds, external services, design/ensemble voices, overridden dispatch, unrecorded preloaded models, unsupported model/runtime dependencies, macOS and Windows continue ordinary temporary synthesis. Enabling recovery after a model was loaded requires a legitimate engine reload before that model can acquire load-time evidence.

A retry matches the captured book, chunk UID, take/input revision, prepared text and window plan, effective voice/instruction/seed, model assets, actual serving code, tokenizer policy, generation settings and runtime contract. Current filesystem names never relabel an already loaded model. Every reused window is copied privately, checked for exact bytes and PCM metadata, and fully validated for finite speech. AA2 renews live book/task ownership and serving identity after the copy. Dependency drift aborts the parent rather than mixing windows from different serving settings. Fixed seeds identify a request; they do not promise identical audio across runtimes.

The private `.synthesis-recovery-v1` namespace has a checksummed index, immutable completed WAVs and charged interrupted writes. Bounds include 16 pending parents, 1024 windows per parent, 64 MiB per artifact and a 4 MiB index. Reaching a limit, cache contention or cache IO failure skips caching while ordinary validated rendering continues under the bound serving identity. Older interrupted requests can be retired for capacity; active-task parents are protected. Completed evidence is retired only after the complete replacement and its revision-bound receipt have been attached through the normal Project metadata commit. A cleanup failure preserves the successful take.

**Clear retained recovery windows** removes only artifacts owned by a valid index while tasks are idle. Open Editor first so the action can carry the current book token. Saved takes, unrelated files and the persistent cache lock are kept. Damaged/missing index authority and unsafe aliases cause refusal; unknown files are preserved for inspection. Clearing does not scan or reset an unknown namespace. Native/listening qualification and additional platforms/voice categories remain tracked in issue #1436.

## Saved external server schema check

Setup → Speech engine includes an explicit **Check saved server** action beside the saved-server number. The first or only saved URL is number 1; a saved pool uses its line order. The action never runs on page load or when the mode changes, never accepts a typed URL, never saves settings, and never generates audio. It asks the already saved external server for its declared schema through a fresh owned SDK process; that fresh process is the overhead of each explicit check and is not reused as generation state.

Supported schema operations are `custom` and `clone`, reported as `supported`, `unsupported`, or `unknown` with endpoint, adapter, required/missing fields, and refusal details. The explicit endpoint pairs are `/generate_custom_voice` or `/custom_voice`, and `/generate_voice_clone` or `/voice_clone`. Parameter aliases are `instruct_text` for `instruct` and `audio` for `ref_audio`. The adapter maps requested size `1.7B` to `Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice` for custom or `Qwen/Qwen3-TTS-12Hz-1.7B-Base` for clone only when the declared schema accepts `model_id`. It forwards requested seeds, never silently drops semantic inputs, and rejects missing seed support, conflicting aliases, incompatible values, and unknown required fields before prediction. Server-declared defaults allow omission of unrelated optional fields. Design and ensemble are not server operations supported by these adapters.

Every compatible generation also starts a fresh owned SDK process so it cannot trust constructor-cached schema from an earlier request. Constructor and metadata overhead count inside the existing external-call deadline. This favors current-schema validation over SDK-cache reuse; the generic internal transport still retains its original caching behavior. No live server/model combination is qualified by this change. The local compatibility matrix consists only of synthetic CustomVoice/clone schemas and owned-process fixtures, not model inference or listening evidence.

The report describes schema compatibility only. It does not prove reachability, does not prove audio will be produced, and is not live qualification. Every generation call revalidates compatibility afresh, so a passing check never replaces the generation-time check. Evidence for the schema contract is synthetic only in this repository; a synthetic report is not evidence about a particular deployed server.

Inspection sends no source text, reference audio, or reference text to the external server. Only the saved server address, the saved-server index, and the capability request are used. If saved TTS settings change during the check, the stale report is discarded. Edit the unsaved form and the check tells you to Save Configuration first instead of presenting compatibility for settings that are not saved.

Only one explicit inspection runs per application process; overlapping requests receive a retryable refusal. Its 10-second diagnostic deadline is separate from the saved generation timeout. All saved endpoint settings, including an unused primary URL when a pool is selected, must match the form before a report is displayed. Unknown reports never authorize generation. When the metadata envelope cannot be inspected, the fallback fingerprint identifies only the endpoint/adapter; a bounded metadata envelope retains its schema identity even when one operation is unknown.

The 128 KiB schema limit applies after the SDK materializes metadata; it is not a streaming HTTP response or process-memory limit. Constructor/schema fetching remains inside the owned subprocess and request deadline, but this does not qualify a hostile server's memory behavior. Server defaults cannot select reference files or replace omitted semantic inputs: generation supplies those explicitly. Returned audio is independently owned until its prediction context closes, even if a subsequent call refreshes the SDK worker.

The schema budget counts canonical UTF-8 JSON, with a separate 16 KiB protocol response budget reserving envelope space. Resource-limit refusals are reported as inspection limits, not malformed schemas. Unknown types on one operation do not erase a valid sibling operation; unrelated defaulted parameters are omitted, never filled from remote defaults. Known model options must include this adapter's 1.7B contract; speaker and other requested values are still validated separately on every generation. No report qualifies a saved voice assignment or audio quality.

The Check button permits only one in-flight click and distinguishes configuration, stale/busy and cleanup refusals without exposing remote error bodies. Blank timeout fields use the same 300-second default as Save Configuration. Owned SDK workers disable Hugging Face telemetry. A worker or cleanup failure fails the request and keeps the previously published take; completed but uncommitted replacement audio is not a recovery artifact or permission to publish past a failed ownership gate.
