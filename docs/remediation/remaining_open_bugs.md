## Fixed

- #804: Windows render admission no longer asks a possibly disabled WSL Bash to resolve the default GPU lock. One pure standard-library resolver is used directly by the native app and by the existing shell queue CLI. The same lock path, portable exclusive kernel lock, configured overrides, contention checks and inherited-owner proof are preserved. Only acquiring a default Windows lock creates its parent directories; read-only probes do not. A Bash-unavailable regression fails on original code and passes after the fix, with a held lease refusing another acquisition and release restoring availability. The native Windows CI diagnostic now exercises real audio-task admission with an empty PATH, cross-process lock contention, duplicate refusal and release. Native Windows evidence is pending that CI run; local Windows dispatch uses a simulation on Linux, with real Linux kernel file locks.
- #746: llama.cpp /props reads at most 1 MiB plus one overflow byte, and refuses oversized replies before JSON parsing. The existing timeout, runtime dispatch and unsupported-route cache remain. Oversize rejection does not poison the miss cache, so a later healthy reply can recover. Three regression cases fail on original code; the fixed 26-test status/recovery/dispatch group passes without skips, including exactly-at-limit admission and one-byte-over refusal.
