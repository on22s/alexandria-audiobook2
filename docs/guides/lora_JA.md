# Alexandria 向け Qwen3-TTS LoRA 学習ガイド

## LoRA とは（やさしい説明）

LoRA（Low-Rank Adaptation）は、TTS モデル全体を再学習せずに、**新しい声を教える**方法です。次のように考えてください。

- ベースの TTS モデルはすでに話し方を知っています。ただ、**あなたの特定の声**を知らないだけです。
- LoRA アダプターは小さなファイル（通常 100 MB 未満）で、あなたの声がどんな響きかをモデルに教えます。
- 学習が終われば、このアダプターを使って TTS モデルにその声で一貫して話させられます。

### 対象となる人

- **プロジェクトをまたいで再利用できる、常設のカスタムボイス**が欲しい。
- 複製したい声の**きれいな音声サンプル**がある（短いクリップが最低 30 個）。
- **VRAM 8 GB 以上の GPU**がある（16 GB 以上を推奨）。

### Alexandria のほかの部分との関係

1. **Dataset Builder タブ** — 学習データセット（音声クリップとテキスト）を作る場所。
2. **Training タブ** — LoRA 学習を実行する場所。
3. **Voices タブ** — 「LoRA Voice」を選び、アダプターファイルを指定して学習済みの LoRA アダプターを使う場所。

### クイックスタート：最初の声を学習する

#### ステップ 1：音声を用意する

複製したい声の**短い音声クリップが 30〜120 個**（各 2〜10 秒）必要です。

- 録音が明瞭で、背景ノイズが少ない。
- 各クリップは、話された 1 文か 1 フレーズ。
- WAV ファイルで保存（16-bit、24 kHz を推奨）。

#### ステップ 2：データセットを作る

Alexandria の Web UI で次の操作をします。

1. **Dataset** タブを開きます。
2. 音声クリップを 1 つずつアップロードします。
3. 各クリップについて、話されたテキストを入力します。
4. 終わったら **Save Dataset** をクリックします。

#### ステップ 3：LoRA アダプターを学習する

1. **Training** タブを開きます。
2. データセットを選択します。
3. 最初の学習には次の設定を使います。
   - **Epochs:** 9〜10（約 60 サンプルの場合）
   - **Learning Rate:** 1e-6（アプリの既定値）
   - **LoRA Rank:** 64
   - **LoRA Alpha:** 128
   - **Gradient Accumulation:** 4
4. **Start Training** をクリックします。
5. **Loss** の数値を確認し、**4.1〜4.2** になったら学習を止めます。

#### ステップ 4：新しい声を使う

1. **Voices** タブを開きます。
2. 声の種類として **LoRA Voice** を選びます。
3. 学習したアダプターファイルを指定します。
4. 新しい声を使える状態になりました。

### Loss の数値の読み方

**Loss** は、モデルがあなたの声をどれだけ学習できているかを表します。

- **4.5 より高い：** 声は明瞭だが、目標の声にあまり合っていない（学習不足）。
- **4.1〜4.2：** 最適な範囲。音声が明瞭で、声もよく合い、指示にも従う。
- **4.1 未満：** 音声が崩れたり壊れたりする危険（学習過多）。**すぐに学習を止めてください。**
- **3.5 未満：** 音声が一貫して崩れている。学習しすぎです。

**目安：** 数分おきに loss を確認します。4.15 になったら学習を止めます。それ以上下げないでください。

## クイックリファレンス

| データセットの大きさ | Epochs | Learning Rate | LoRA r | LoRA Alpha | Grad Accum | 目標 Loss |
|-------------|--------|---------------|--------|------------|------------|-------------|
| 約 30 サンプル | 1e-6 では未測定 | 1e-6 | 64 | 128 | 4 | 4.1〜4.2 |
| 約 60 サンプル | 9〜10 | 1e-6 | 64 | 128 | 4 | 4.1〜4.2 |
| 約 120 サンプル | 1e-6 では未測定 | 1e-6 | 64 | 128 | 4 | 4.1〜4.2 |

> **学習率は 1e-6 を使ってください。** このガイドの以前の版は 2e-6〜5e-6 を勧めていました。
> 5e-6 で学習したアダプターは話し終わらなくなります。発話の終わりを出さないのに学習の loss は
> 正常に見えるため、loss では気づけません（[RECIPES.md](../../RECIPES.md) を参照）。上の
> 9〜10 エポックは、このガイド末尾の表にある 61 サンプル・1e-6 の学習（male-lora-03 と -05）
> に基づきます。ほかのデータ量は 1e-6 で測定していないので、loss を見つつ結果を試聴してください。

**目標 loss：4.1〜4.2** — 声のアイデンティティ、instruct への追従、明瞭な音声のバランスが最も良い範囲です。loss 4.1 が下限で、これを下回ると崩れる可能性が高まります。同じ設定でも実行ごとに loss が少し変わることがあるため、余裕を見て 4.15〜4.2 を目指してください。

## 重要な原則

- **データが多いほど epochs は少なく。** データセットが大きいほど 1 epoch で多くのことを学ぶため、過学習までの回数が少なくて済みます。
- **総学習量が重要。** サンプル数 × epochs は、合計 250〜400 回程度の forward に収めるのが目安です。600 を超えると過学習の危険があります。
- **loss が 4.1 未満なら崩れる危険。** 実行ごとのばらつきにより、同じ設定でも 4.1 のどちら側に転ぶかが変わります。3.5 未満では、出力が一貫して崩れるか、EOS に到達しなくなります。
- **loss が 4.5 より上なら学習不足。** 音声は明瞭でも声のアイデンティティが弱く、instruct への追従もわずかです。

## 各設定の働き

| 設定 | 効果 |
|---------|--------|
| **Epochs** | データセットを何周するか。多いほどよく合わせ込む。 |
| **Learning Rate** | 1 ステップで重みをどれだけ動かすか。高いほど速いが危険。 |
| **LoRA Rank (r)** | アダプターの容量（学習可能な次元数）。64 が良い既定値。 |
| **LoRA Alpha** | スケーリング係数。Alpha/r の比が実効的なアダプターの重みを決める。128/64 = 2 倍が検証済みの既定値。 |
| **Grad Accumulation** | より大きなバッチサイズを模擬する。多くの場合 4 で安定。 |
| **Batch Size** | 1 ステップあたりのサンプル数。1 のままにする（VRAM の制約）。 |

## 過学習の症状

| Loss | 音声品質 | instruct への追従 | 判断 |
|------|--------------|-------------------|---------|
| 4.4 以上 | 明瞭、崩れなし | わずか／弱い | 学習不足 |
| 4.1〜4.2 | 明瞭、表現豊か | 良好 | 最適な範囲 |
| 3.9〜4.1 | 表現豊かだが崩れる危険 | 強い | 際どい — 実行ごとのばらつきで崩れることがある |
| 3.4〜3.8 | 崩れているが読める | 強い | 過学習が始まっている |
| 3.0〜3.3 | 崩れ／EOS なし | 該当なし | 過学習、使用不可 |

## データセットの準備

### Dataset Builder を使う（推奨）

1. Alexandria の **Dataset** タブを開きます。
2. 声の説明を入力し、行（感情とテキストの組）を追加します。
3. サンプルを生成します。各行が VoiceDesign で WAV を作ります。
4. 明瞭で代表的な行を**参照サンプル**として選びます（学習時の話者埋め込み用の `ref.wav` になります）。
5. データセットとして保存します。学習用フォルダーが自動で作られます。

### 良いデータセットのコツ

- **多様性を入れる：** 感情、速さ、音量、文の長さを混ぜます。
- **短い発話を入れる：** 「Oh!」「Hmm.」「Right.」など。短い入力での EOS の挙動をモデルが学ぶ助けになります。
- **中立的な文章で終える：** 長く穏やかな描写の段落は、参照サンプルとして理想的です。
- **参照サンプルは seed を固定する。** 再生成しても話者埋め込みが安定します。
- **合計 15〜30 分**の音声が、プレミアムな声プロファイルの目安です。

### データセットの構造

```
lora_datasets/{name}/
├── metadata.jsonl      # {audio_filepath, text} per line
├── ref.wav             # Reference audio for speaker embedding
├── ref_text.txt        # Transcript of ref.wav (must match exactly)
└── sample_000.wav ...  # Training audio files
```

### メタデータの形式

```json
{"audio_filepath": "sample_000.wav", "text": "I told you never to come back here!"}
{"audio_filepath": "sample_001.wav", "text": "I just don't know what to do anymore."}
```

## 多言語

単一言語のデータで学習した LoRA アダプターは、その言語のアクセントと発音を身につけます。英語のサンプルで学習したアダプターは、ドイツ語のテキストを英語の発音で読み上げます。ベースモデルが十分な手がかりを与えて許容できる結果になることもありますが、一貫しません。

**話者ごと・言語ごとに別の LoRA を学習してください。** アダプターが学んだ音韻と戦わずに、きれいな発音になります。

### 新しい言語と声のアイデンティティ

このガイドの loss の目標（4.1〜4.2）は、**英語の声のアイデンティティ**を学習する場合のもので、ベースモデルがすでにその言語を知っていて、アダプターは新しい声だけを学ぶ前提です。**ベースモデルがネイティブに扱えない言語**で学習する場合、アダプターは新しい音韻と声のアイデンティティの両方を同時に学ぶ必要があります。これはより難しい課題で、過学習の境界が上にずれます。

| 学習の目的 | 目標 Loss | 崩れ始める下限 |
|--------------|-------------|--------------|
| 声のアイデンティティ（対応言語） | 4.1〜4.2 | 約 4.1 |
| 新しい言語＋声のアイデンティティ | 4.5〜5.5 | 約 4.1〜4.5（絶対値が近くても崩れる） |

新しい言語では、学習率をかなり低くし、最終的な loss が高くなることを見込んでください。loss 5.0〜5.5 でも、発音が良く自然できれいな音声になることがあります。アダプターが言語を学びつつ、過学習まで押し込まれていない状態です。この高い loss では instruct への追従は弱くなりますが、声のアイデンティティと発音が優先です。

**検証した例：** カタルーニャ語の女性、2321 サンプル、1 epoch、lr=2e-7、r=64、alpha=128 — 最終 loss 5.38、適切なカタルーニャ語の発音できれいな音声。以前 lr=1e-5（loss 3.78）で試したときは、英語の声のアイデンティティの「通常」範囲に入っていても、崩れた出力になりました。

## トラブルシューティング

| 問題 | 原因 | 対処 |
|---------|-------|-----|
| 新しいテキストで音声が崩れる | 過学習（loss が低すぎる） | epochs か lr を下げる |
| 生成が止まらない／EOS がない | 深刻な過学習 | epochs を減らして再学習 |
| 明瞭だが声が似ない | 学習不足（loss が高すぎる） | epochs か lr を増やす |
| 早口になる | 学習データの話す速さが速かった | instruct で「slow, even narration」を使うか、データセットを作り直す |
| 短いテキストが max_new_tokens で止まる | 短い発話の EOS をモデルが学んでいない | 短い発声を学習データに追加 |
| 冒頭の音声が乱れる | Clone プロンプトの位置合わせの副産物 | 軽微。通常はオーディオブック全体の生成では出ない |
| ref.wav の不一致 | ref_text.txt が ref.wav の内容と合っていない | ref_text.txt に ref.wav の正確な文字起こしを入れる |
