# Google Colab

一時的な GPU セッションには [main ブランチのノートブック](https://colab.research.google.com/github/on22s/alexandria-audiobook2/blob/main/alexandria_colab.ipynb) を使ってください。GPU の空き状況とセッションの寿命は一定ではありません。切断前に作業を保存してください。通常の Web UI 起動では、公開 ngrok トンネルが開きます。アクセスを共有する前に[認証](../../README.md#authentication-optional)を確認し、トークンと API キーは非公開にしてください。

## セッションを開始する

1. **Runtime → Change runtime type → T4 GPU** を選び、**Check GPU Runtime** を実行します。
2. **Install Alexandria** を実行し、正常に終わるまで待ちます。ノートブックのカーネルの Python で、アプリと Qwen-TTS の依存関係をまとめて導入します。Git やパッケージの失敗はセルを停止します。インストールに失敗したまま Start へ進まないでください。
3. 任意で、**最初のモデル読み込みより前に** Drive をマウントします。Hugging Face のモデルキャッシュの場所が変わります。本、声の割り当て、生成した音声、Ollama の別キャッシュは自動ではバックアップされません。
4. ngrok を設定して **Start Alexandria** を実行します。サーバーの準備完了チェックを待ち、表示された URL を開きます。LLM はアプリの **Setup** タブで設定します。
5. ローカル LLM を使う場合は **Install Ollama for Local LLM** を実行します。それ以外は、選んだ API プロバイダーを設定します。ホスト型 API は利用料金がかかることがあります。

セルはセクション見出しの順に実行してください。**Stop Ollama** と **Stop Server** は後片付けの操作であり、サービス起動直後に実行するセットアップ手順ではありません。

## T4 を LLM と TTS で共有する

Ollama とローカル TTS は同じ VRAM を取り合います。台本生成、レビュー、ペルソナ、その他の LLM タスクを先に終わらせます。その後、バッチ TTS の前に **Stop Ollama** を実行します。このセルは、このノートブックが起動したプロセスツリーだけを終了し、実際のデバイスメモリーのスナップショットを表示します。ほかのプロセス、キャッシュ、コンテキストがまだメモリーを保持していることがあり、プロセスを止めても一定量が解放される保証はありません。

セットアップ用セルは、そのポートに既存のリスナーがあると拒否します。無関係な Ollama サービスを引き継いだり停止したりはしません。所有権の記録がない場合、起動の失敗、後片付けの失敗はエラーになります。所有者を復元できない場合は、ランタイムを置き換える前に作業をダウンロードしてください。プロセス名で広く一括停止するコマンドは使わないでください。

コンテキストと出力の上限は、推論サーバーの実際の容量の範囲内に保ってください。アプリの設定を増やしても、Ollama の読み込み済みコンテキストは広がりません。アプリの GPU／余裕の保護と、ワーカーを段階的に減らす再試行は有効なままにします。後で LLM の作業に戻る場合は、先に TTS を終わらせ、別のモデルを読み込む前に使用可能な VRAM を確認してください。

## インストールや起動の失敗を診断する

インストール用セルは、子プロセスの stdout と stderr を表示します。最後の pip の要約より上で、**最初に失敗したパッケージとそのトレースバック**を探します。後から出るモジュール不足のエラーは、不完全なインストールの結果であることがあります。そのモジュールだけを入れても、ほかの要件が欠けたままになる可能性があります。

現在の要件は、旧来の `romkan==0.2.1` ではなく `romkan2` を使います。`romkan==0.2.1` は setup で、新しい Python では削除された `imp` を import するためです。アプリは Python 3.13 互換の設定アノテーションも使います。古い保存済みコピーを使っている場合は、main からノートブックを開き直してください。チェックアウトを更新するだけでは、ブラウザーに読み込み済みのコードセルは更新されません。古いセルを新しいチェックアウトに対して実行し続けないでください。

エラーを報告するときは、カーネルのバージョンと実行ファイルを記録します。

```python
import sys
print(sys.version)
print(sys.executable)
```

失敗したパッケージ名、そのトレースバック、関連する導入済みバージョンを含めてください。認証情報と本の非公開テキストは削除します。依存関係の警告がすべて致命的なエラーを示すとは限りません。ランタイムが変わると再インストールが必要なことがあるため、再起動前に作業を保存してください。

アプリの起動、モデルのダウンロード、生成については **View Server Logs** を使ってください。アプリのログは `/content/Alexandria/colab-server.log` で、ローテーションされたバックアップが 2 つあります（合計最大 3 MiB）。ビューアーは直近の 64 KiB から表示します。ビューアーを中断してもサーバーは動き続けます。起動の失敗時にも直近の末尾が表示されるので、必要なログはランタイムが消える前にダウンロードしてください。

## 結果を保存して検証する

モデルは初回利用時にダウンロードされ、それぞれ数 GB を占めることがあります。永続ストレージがない場合、新しいランタイムでは再度ダウンロードが必要です。セッションを終える前に、完成したオーディオブックをダウンロードし、必要な台本、声の割り当て、ログを保存してください。任意の Drive キャッシュは、プロジェクト全体のバックアップではありません。

インストールの成功、HTTP の起動チェック、短いプレビューは、本全体、すべての声の種類、聴感品質を検証したことにはなりません。要求したすべてのチャンクが完了したことを確認し、結果を書き出して再生してください。現在の Colab ランタイムに関する知見と本全体の検証は、[issue #1278](https://github.com/on22s/alexandria-audiobook2/issues/1278) で追跡しています。

終了時は **Stop Server** を使ってください。トンネルの後片付けに失敗しても、サーバーとノートブック所有の Ollama の後片付けを試みます。報告された後片付けのエラーには対応が必要です。
