# Alexandria 的 Qwen3-TTS LoRA 训练指南

## 什么是 LoRA？（大白话）

LoRA（Low-Rank Adaptation，低秩适配）是一种**给 TTS 模型教一个新声音**的办法，不需要把整个模型重训一遍。可以这样理解：

- 基座 TTS 模型本来就会说话——它只是不认识**你这个特定的声音**
- LoRA 适配器是一个小文件（通常不到 100 MB），它教模型你的声音听起来是什么样的
- 训练好之后，用这个适配器就能让 TTS 模型稳定地用那个声音说话

### 这是给谁用的？

- **你想要一个能长期复用、跨项目使用的自定义声音**
- **你手上有想克隆的那个声音的干净音频样本**（至少 30 段短片段）
- **你有一块 8 GB 以上显存的 GPU**（推荐 16 GB 以上）

### 这和 Alexandria 的其他部分是什么关系？

1. **Dataset Builder 页**——在这里创建训练数据集（音频片段 + 文本）
2. **Training 页**——在这里跑 LoRA 训练
3. **Voices 页**——在这里使用训练好的 LoRA 适配器：选择 "LoRA Voice"，指向适配器文件

### 快速开始：训练你的第一个声音

#### 第 1 步：准备音频

你需要**30–120 段短音频**（每段 2–10 秒），都是你想克隆的那个声音：
- 录音干净，背景噪声尽量少
- 每段应该是一句话或一个短语
- 保存为 WAV 文件（推荐 16-bit、24 kHz）

#### 第 2 步：创建数据集

在 Alexandria 的 Web UI 里：
1. 打开 **Dataset** 页
2. 一段一段地上传音频
3. 为每段输入当时说的文本
4. 完成后点 **Save Dataset**

#### 第 3 步：训练 LoRA 适配器

1. 打开 **Training** 页
2. 选择你的数据集
3. 第一次训练用这些设置：
   - **Epochs:** 5-8（约 60 个样本时）
   - **Learning Rate:** 3e-6
   - **LoRA Rank:** 64
   - **LoRA Alpha:** 128
   - **Gradient Accumulation:** 4
4. 点 **Start Training**
5. 盯着 **Loss** 那个数字——降到 **4.1-4.2** 就停

#### 第 4 步：使用你的新声音

1. 打开 **Voices** 页
2. 声音类型选 **LoRA Voice**
3. 指向你训练好的适配器文件
4. 新声音就可以用了！

### 怎么看懂 Loss 这个数字

**Loss** 衡量的是模型学你这个声音学得有多好：
- **高于 4.5：** 声音清楚，但和目标音色对不上（训练不足）
- **4.1-4.2：** 最佳区间——音频清楚、音色匹配、能听指令
- **低于 4.1：** 有出现乱码或坏音频的风险（过拟合）——**立刻停止训练**
- **低于 3.5：** 音频会稳定地变成乱码——你训练太久了

**经验法则：** 每隔几分钟看一次 loss。到 4.15 就停。不要再往下压。

## 速查表

| 数据集大小 | Epochs | 学习率 | LoRA r | LoRA Alpha | 梯度累积 | 目标 Loss |
|-------------|--------|---------------|--------|------------|------------|-------------|
| 约 30 个样本 | 10-15 | 5e-6 | 64 | 128 | 4 | 4.1-4.2 |
| 约 60 个样本 | 5-8 | 3e-6 | 64 | 128 | 4 | 4.1-4.2 |
| 约 120 个样本 | 3 | 2e-6 | 64 | 128 | 4 | 4.1-4.2 |

**目标 loss：4.1-4.2**——这是音色身份 + 听从指令 + 干净音频三者的最佳平衡点。4.1 是地板；低于它，出乱码的可能性会越来越大。注意同一套设置在不同次运行中得到的 loss 会有细微差别，所以为了有可靠的余量，瞄 4.15-4.2。

## 关键原则

- **数据越多，epoch 越少。** 数据集越大，每个 epoch 教的东西越多，所以在过拟合之前需要的轮数更少。
- **总曝光量很重要。** 样本数 × epoch 大致应落在 250–400 次前向传播。超过 600 就有过拟合风险。
- **loss 低于 4.1 = 乱码风险。** 运行间的波动意味着同一套配置可能落在 4.1 的任意一侧。低于 3.5 时，输出会稳定地变成乱码，或者到不了 EOS。
- **loss 高于 4.5 = 训练不足。** 音频清楚，但音色身份弱，听指令也很勉强。

## 每个设置做什么

| 设置 | 作用 |
|---------|--------|
| **Epochs** | 完整过一遍数据集的次数。越多拟合越紧。 |
| **Learning Rate** | 每步调整多少权重。越高学得越快，风险也越大。 |
| **LoRA Rank (r)** | 适配器的容量（可训练维度的数量）。64 是个好默认值。 |
| **LoRA Alpha** | 缩放系数。Alpha/r 的比例决定适配器的有效权重。128/64 = 2 倍是测过的默认值。 |
| **Grad Accumulation** | 模拟更大的批大小。4 在多数情况下稳定。 |
| **Batch Size** | 每步的样本数。保持为 1（受显存限制）。 |

## 过拟合的症状

| Loss | 音频质量 | 听从指令 | 结论 |
|------|--------------|-------------------|---------|
| 4.4+ | 清楚，无乱码 | 轻微/勉强 | 训练不足 |
| 4.1-4.2 | 清楚，有表现力 | 好 | 最佳区间 |
| 3.9-4.1 | 有表现力但可能乱码 | 强 | 刀刃上——运行间波动可能导致乱码 |
| 3.4-3.8 | 乱码但还能听懂 | 强 | 开始过拟合 |
| 3.0-3.3 | 乱码 / 无 EOS | 不适用 | 已过拟合，不可用 |

## 数据集准备

### 用 Dataset Builder（推荐）

1. 在 Alexandria 里打开 **Dataset** 页
2. 填一个声音描述，添加若干行（情绪 + 文本）
3. 生成样本——每一行通过 VoiceDesign 产生一个 WAV
4. 挑一行清晰、有代表性的作为**参考样本**（训练时用作说话人嵌入的 `ref.wav`）
5. 保存为数据集——会自动创建训练文件夹

### 好数据集的要点

- **要有变化：** 混合不同情绪、语速、音量和句长
- **要有短句：** "Oh!"、"Hmm."、"Right."——有助于模型学会在短输入上的 EOS 行为
- **以一段中性文本收尾：** 一段长而平静的描写性文字是理想的参考样本
- **参考样本用固定种子**，这样重新生成时说话人嵌入保持稳定
- **15–30 分钟**的总音频量是做一个高级声音档案的目标

### 数据集结构

```
lora_datasets/{name}/
├── metadata.jsonl      # {audio_filepath, text} per line
├── ref.wav             # Reference audio for speaker embedding
├── ref_text.txt        # Transcript of ref.wav (must match exactly)
└── sample_000.wav ...  # Training audio files
```

### 元数据格式

```json
{"audio_filepath": "sample_000.wav", "text": "I told you never to come back here!"}
{"audio_filepath": "sample_001.wav", "text": "I just don't know what to do anymore."}
```

## 多语言

用单一语言数据训练的 LoRA 适配器会带上那个语言的口音和发音。用英语样本训练的适配器去读德语文本，会读出英语发音——基座模型偶尔能给出足够的指引让结果可以接受，但不稳定。

**为每个说话人的每种语言单独训练一个 LoRA。** 这样能得到干净的发音，而不必去和适配器学到的音系较劲。

### 新语言 vs. 音色身份

本指南里的 loss 目标是针对**英语音色身份**训练定的，前提是基座模型本来就会这门语言，适配器只需要学一个新声音。而训练**基座模型并不原生支持的语言**时，适配器必须同时学新的音系和音色身份。这件事更难，会把过拟合的边界往上推：

| 训练目标 | 目标 Loss | 乱码地板 |
|--------------|-------------|--------------|
| 音色身份（受支持的语言） | 4.1-4.2 | 约 4.1 |
| 新语言 + 音色身份 | 4.5-5.5 | 约 4.1-4.5（在相近的绝对 loss 上仍会乱码） |

对新语言，请用低得多的学习率，并且预期最终 loss 更高。5.0-5.5 的 loss 可以产生干净自然的语音和良好的发音——适配器学会了这门语言，但还没被推到过拟合。在这些更高的 loss 上，听从指令会弱一些，但音色身份和发音才是优先项。

**测过的例子：** 加泰罗尼亚语女声，2321 个样本，1 个 epoch，lr=2e-7，r=64，alpha=128——最终 loss 5.38，语音干净，加泰罗尼亚语发音正确。早前在 lr=1e-5（loss 3.78）的尝试，虽然落在英语音色身份的"正常"区间里，输出却是乱码。

## 故障排查

| 问题 | 原因 | 修复 |
|---------|-------|-----|
| 新文本上音频乱码 | 过拟合（loss 太低） | 减少 epoch 或 lr |
| 生成卡住 / 没有 EOS | 严重过拟合 | 用更少的 epoch 重训 |
| 清楚但没有音色身份 | 训练不足（loss 太高） | 增加 epoch 或 lr |
| 语速过快/赶 | 训练数据的语速就快 | 在 instruct 里写 "slow, even narration"，或者重新调整数据集 |
| 短文本卡在 max_new_tokens | 模型没学会短句的 EOS | 往训练数据里加短促发声 |
| 开头有音频杂音 | 克隆提示词的对齐伪影 | 影响小——完整有声书生成时通常不会出现 |
| ref.wav 不匹配 | ref_text.txt 和 ref.wav 的内容对不上 | 确保 ref_text.txt 是 ref.wav 的精确转写 |
