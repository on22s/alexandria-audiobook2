# 录音历史

在 Editor 的 Inspector 里打开 **Automatic take history**，选择 **Refresh setting**，
然后点 **Turn on**。这个项目设置默认关闭，只对之后的重生成生效。不选中任何行也可以改。

开启后，在生成或装入替代音频之前，会先保留当前选中的那条旧录音（take）。修改文字、说话人、
演绎指令或录音编号时，原始存档演绎的元数据保持不变。反复编辑不会用新的文字给旧音频
重新贴标签。首次生成没有旧录音可归档。

用 Inspector 的快照控件试听已保存的演绎、保护一份副本、删除（可撤销），或在确认后
永久移除。项目归档视图里也有更早的整书生成记录。试听不会把某个快照选为当前音频。

在支持的 Linux 主机上，如果一个快照带有当前书和当前行的发布证据，就会提供
**Check & restore**。使用前请先保存待处理的编辑。音频任务会检查原始输入、声音和种子、
模型设置、发音、合成窗口、本机执行依赖和实际保存的字节。检查过程可能加载本机声音模型，
但不会合成新音频。用 **Cancel audio task** 请求取消，并等待任务结束。

恢复成功后，会选中原来的编码字节、录音编号和产物修订，并保留它们的生成回执。即使自动
历史已关闭，也会把被替换的那条演绎留在历史里。它不会改写文字、说话人或演绎指令。依赖
发生变化或证据不可用时会拒绝恢复，并保留当前选中的演绎。较早的快照、其他书/行身份和
不受支持的主机仍然可以试听。受保护的快照可以恢复；已删除的快照必须先撤销删除。

归档允许 4,096 条记录、每行 16 条、音频负载合计 1 GiB。已删除和中断的副本在永久移除
之前仍计入配额。仍被待处理的替换或正在进行的分块删除撤销所需的副本不能被移除。如果
准入失败，请先腾出归档空间，或先关闭自动历史，再重试生成。关闭时，已有副本仍然可用。
显式恢复仍然需要足够的空间来保留被替换的那条录音。

如果生成被取消或发布失败，保留下来的旧演绎会一直受保护，直到有一次替换成功。进程中断
后，不完整的归档副本仍然可见并计入配额；重试前请显式移除该副本。已完成的保留副本可以
在重试时复用，即使它原来的工作音频位置已经变了。损坏的策略可以通过刷新该设置再关闭来
替换，不需要解析或重写归档。

开启历史无法重建被更早的编辑已经分离出去的音频。重建分块或加载另一本书会创建新的
书/行身份；自动保留不会在这些变化之间迁移待处理的行元数据。已完成的归档副本仍可在
项目归档中找到。

快照保留的是实际保存的字节和记录下来的输入。仅靠生成快照并不能证明早先渲染所用的确切
依赖。在把候选音频用于有声书之前，请先试听。

开启自动历史后，符合条件的、内置的本地 CustomVoice 渲染还会记录一份有大小上限的发布
回执。这目前要求确定性种子、内部合成窗口，以及合格的恢复服务身份。实际观察到的语音
输入独立于 ASR 捕获，然后与成品编码文件的哈希和解码后的形状绑定。被选中的声音/模型输入、
发音决策、窗口策略、书/行身份和音频修订也会一并绑定。其他渲染和更早的快照仍然没有证明。
已有快照不会被追溯认证。回执只是一个恢复候选；显式操作仍然要验证它当前的依赖和音频。

发布回执和待处理的前驱元数据共用每本书 16 MiB 的预算。每份发布回执最多 4 KiB；不可变的
归档记录/负载上限仍然适用。符合条件的第一遍音频如果超出回执的 64 MiB、单声道/立体声、
192 kHz 和十分钟这些边界，可以不带证明发布。新生成会随音频选择原子地替换它原先的回执，
或者在拿不到完整证明时清除它。浏览历史不会加载模型、不会对选中的音频做哈希，也不会运行
语音验证。

## MPEG 校验与解码器可用性

MPEG 快照在变为就绪之前会用 FFprobe 和 FFmpeg 独立检查。解码器通过可定位的描述符输入
读取已准入的打开文件，检查完整的 PCM 帧数和几何参数，并重新检查源内容。它不会重采样、
归一化或替换归档原件。WAV、FLAC 和 OGG 快照沿用现有的校验路径；归一化范围之外的有限
浮点 WAV 采样仍然接受。

这要求 FFprobe 和 FFmpeg 是可用的构建，并且支持可定位的 `fd` 输入。如果缺失或不支持，
请更新解码器工具。捕获失败或被取消时，待处理的副本和配额占用都会保留；重试前请显式移除
不完整的副本。当前选中的演绎会被保留。

这套共用解码器也保护立体声 MPEG 训练参考的转换：私有检查点暂存区会在发布前收到完整的
单声道转换，而原始参考保持不变。解码器超时会停止并回收自己拥有的进程。调用方的写文件
回调在写入返回之前一直保有所有权；被阻塞的文件系统写入不会在超时后被放弃。

## 紧凑元数据

归档写入可以把重复的文本、生成输入、来源信息和合成策略只存一次，用内容哈希寻址。只有当
这样做至少能省下 4 KiB 且占清单字节的 5% 时才会使用紧凑格式。完整的原始回执和选中的音频
含义不变。同样的记录数、音频、深度和完整展开后 16 MiB 清单上限仍然适用。这减少了重复元
数据；每次保存仍会校验并整体替换清单。

已有的 v1/v2 归档仍然可读。紧凑归档使用 v3 格式，旧版本应用会拒绝重写它。要回到旧版应用
之前，请先用当前应用展开元数据。在 `app/` 下、激活应用的 Python 环境后：

```sh
python -m audio_take_history /path/to/project-data --expand-metadata
python -m audio_take_history /path/to/project-data --compact-metadata
```

请使用包含 `take_history/` 的那个数据目录。两个命令都会持有归档锁，并使用它现有的
待处理文件/原子替换边界。转换会保留原来的 v1/v2 写屏障（writer fence）、快照、回执和当前音频选择。
之后的归档写入可能再次把展开的元数据压缩。被引用的负载缺失、发生变化或无效时会拒绝转换；
请保留归档以便检查，不要手动修改引用。移除快照只会丢掉不再被任何保留、已删除或不完整记录
使用的负载。
