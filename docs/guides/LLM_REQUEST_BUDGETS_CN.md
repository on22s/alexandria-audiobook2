# LLM 请求预算

在 **Setup → LLM Settings** 里，每个 Local 或 Remote 配置档都有三个可选的 token 上限：

| 设置 | 留空时的行为 | 作用 |
| --- | --- | --- |
| Total context budget | 可用时使用探测到的已加载上下文 | 限定提示词、输出和安全余量三者之和。声明的值不能把探测到的更小上下文抬高。 |
| Input ceiling | 继承 Advanced 里可选的全局输入上限 | 限定估算出的完整提示词大小，包括指令、角色表和周围文本。 |
| Output ceiling | 不设配置档上限：每个任务保留自己的重试上限 | 设置后，限定补全预算和重试时的提升幅度，包括由提供方计入输出的推理内容。 |

取值必须是正整数。没有通用的最大上限，也没有“无限/绕过”这种设置。输入上限和输出上限是两个独立约束，不表示两者之和一定能塞进已加载的上下文。例如输入上限和输出上限各为 4,096 时，它们在 4,096 token 的上下文里不可能都被用满。

如果已加载的上下文是 8,192，而你声明 4,096，Alexandria 用 4,096。如果已加载的上下文是 4,096，而你声明 8,192，Alexandria 仍然用 4,096。当端点无法暴露自己的上下文时，就由声明来补上缺失的预算。请声明你已加载的模型实际支持的上下文，而不是它宣传的最大值。

更大的三遍源文/上下文目标需要探测到或声明过的上下文。没有的话，启动请求会说明该先设置 Setup 里的哪个字段，然后才去预约后台任务。一个尚未加载的、由 LM Studio 托管的模型算作已知，因为运行会先按计划的上下文把它加载起来。规划和实际发出的 HTTP/手动请求使用同一个上限解析器。超大的提示词会被拒绝；输出预算可能被缩减以塞进剩余上下文。已有的源文保真检查、有界重试和 GPU 准入保持有效。

token 计数沿用现有的保守字符估算，不用提供方专属的分词器。服务端的上下文强制仍然必要。声明更小的预算会限制请求；它不会释放服务器已经分配的显存，也不会重新加载模型。

## 已有配置

对已有配置，在你设定某个配置档上限之前，行为没有任何变化。Baseline Response Tokens 仍然是起始预算而不是硬上限：截断重试仍会把它抬高到各任务自己的上限（三遍流程是 16384，若基准更高则用基准值；审阅是 32768），所以推理模型不会在基准值处被截断。要卡住模型就设置配置档的 Output ceiling；合并上下文检查仍然生效。

不会对已有配置强加新的全局输入上限：它缺省/留空时仍然按上下文检查。配置档的输入上限留空时，会在运行时继承全局值，而不改变已保存的配置档设置。手动传输在把请求交出来供复制之前，会强制同样的声明上限。故障切换使用备用配置档的上限，而不会把它扩大成主模型的预算。
