# 一次性合成工作区的回收

在 Linux 上，由应用拥有的本地合成窗口现在会在写音频之前先登记自己的工作 WAV。参与这一机制的类别有 custom、clone、design、LoRA 和 ensemble。进程死掉之后，下一次空闲时的应用启动或音频任务准入会回收已核验的一次性文件。在可复用片段恢复被关闭时也一样。因此重试可以清掉被遗弃的工作副本，而不会删掉已保存的录音或可复用缓存证据。

对于参与这一机制的本地 Project 路由，原始父 WAV 也有自己的登记，在分配文件之前创建，并一直保留到编码和最终选定录音发布结束。内部的窗口使用另一个工作区；这些窗口做完并不会让原始父级退役。原始父级的所有权独立于可选的合成窗口和可复用恢复。即使两个特性都关闭，默认渲染仍然会捕获一次性清理所需的实时任务、书、UID 和输入授权。它们的可复用缓存、语音输入捕获和发布证明策略保持不变；仅有所有权并不能开启其中任何一项可选特性。

对于原来的 Project 分块编码器，同一份父级登记也拥有编码中间文件及其编码器暂存区。它不会额外分配工作区，也不会削减并行父级预算。MP3 编码和 WAV 回退一直待在那个工作区里，直到现有的选定槽位发布把结果移进 `voicelines`。因此发布前的硬退出留下的是有主的暂存区，而不是一个未登记的 `.chunk-*` 或 `.render-*` 文件。编码器通过一个经过检查的、no-follow 的描述符读取原始父级。它的 PCM、输出和错误文件都以独占方式创建；子进程在读取或截断它们之前，会先核对它们登记过的 inode 身份。WAV 回退还会确认它完成后的文件名仍然指向自己写出的那个文件。完成的 inode 在选定槽位发布过程中保持打开。两次重命名都使用钉住的源目录和目标目录，并且选定的目标必须在元数据变化之前指向同一个 inode。被替换掉的内容会作为证据保留，不能仅仅因为它能被解码成合法音频就变成一个成功的录音。子进程在现有的有界编码器元数据文件里确认自己已刷盘的输出版本。WAV 回退通过持有的描述符核验复制后的字节，分块是可取消的，并且在发布锁之外。相对导入在子进程进入钉住的暂存区之前就已冻结；它的启动 cwd 在启动之前被捕获，这样之后 cwd 变化就不会把那些导入重定向到别处。被覆写的分块读取器、编码器或文件发布辅助函数保持它们原有的暂存行为；不会把这份额外的编码权限交给它们。

同一份捕获到的授权也覆盖参与机制的本地 Project 批处理输出，涵盖 custom、clone、design、LoRA 和 ensemble。每个参与的行都有一个独立的父级工作区，在派发之前分配，并保留到所有批处理收尾逻辑结束。原生的列表批处理、按长度排序、子批次和 OOM 时的尺寸下调都保持不变。内部路由会把项目目录、索引和实时占用绑定到已登记的路径；语音输入捕获使用同一个路径。未映射的行保持正常的输出路径。被覆写的批处理写入器不会拿到已登记的输出路由。

注册表位于项目数据根目录下的 `.synthesis-workspaces-v1/registry.json`。它记录不透明的工区 ID、哈希后的占用/书来源信息、目录身份和声明的窗口数。它不含源文本。清理使用现有的内核任务租约和书锁；有任务在跑或书被占用时，维护会推迟。正常取消会清掉同一个所有者的一次性工作区，而被吊销的所有者会把它留给之后的空闲操作。

单独的 `.synthesis-recovery-v1` 缓存存的是可复用的已核验片段；清掉那个缓存并不授权删除其他文件。已完成的父级发布和已保存录音的挂接保留它们原有的所有权检查。工作区清理失败只会记日志，不会把一个已发布的父级变成失败的渲染。

零窗口的行声明的是仅父级的工作区；普通窗口行仍然声明 2 到 1,024 个窗口。会拒绝零窗口行的旧版应用会保留注册表而不是清理它。请使用理解父级行的版本，以便恢复自动维护。

新启用编码的父级行带一个显式的 `encoding: true` 标记，在任何写入器运行之前与两个目录身份一起提交。它们已有的私有 `join` 目录就是编码器的临时目录。旧的五字段行保持原来的严格 join 文件规则。不认识编码标记的旧客户端会保留注册表并拒绝新的已登记分配；请用能识别编码的版本在降级之前完成空闲维护。已保存的录音和可复用恢复证据与这些一次性行是分开的。

退役使用登记期间捕获的规范书根目录和目录身份。把书根符号链接重定向，无法把清理引到另一本书上。根被替换或所有者被吊销时，会保留原来计费的登记，留待已准入的空闲恢复处理；清理不会去搜索被移动的目录，也不会在失去授权之后强行删除。

## 限制与保留的证据

- 最多登记 256 个工作区，每个最多 1,024 个窗口。这是一次性存储的准入上限；请求的并行 worker 设置保持不变。额度耗尽时会在分配更多工作音频之前拒绝参与机制的渲染。
- 父级和内部窗口的登记共用这 256 个工作区的预算。一个正在跑的、参与机制的带窗口 Project 渲染可能占用两个槽位。容量拒绝绝不会退回到未登记的父级文件。
- 参与机制的批处理行各占一个父级槽位，另外在拆分父级被渲染期间再占一个内部窗口槽位。当前这次批处理尝试的所有父级槽位都必须在提供方开始工作之前获得准入。OOM 重试使用新的作用域和登记；不会复用先前尝试的路径。
- 只有已登记的窗口文件、私有拼装父级和固定的 join 暂存区，以及它们声明的 WAV 设计发布暂存文件是一次性的。未知文件、符号链接、硬链接、已变化的目录身份，以及无效或缺失的注册表授权都会被保留。
- 带编码标记的父级行还会声明固定的 encoded、PCM 和编码器错误文件名。它们钉住的私有 join 目录最多把 16 个常规的、单链接的、当前用户的临时文件（合计最多 8 GiB）委托给编码器。嵌套目录、别名、超量暂存区和不安全的条目会让整条登记被保留。每个声明的子文件都在第一次删除之前被检查；标记不会追溯接管历史文件。
- 在创建目录和提交其身份之间崩溃，可能留下一个空的、含义不明的目录和一个被保留的槽位。任何提供方都不得在身份提交之前写入音频。这个槽位会为显式检查保留；清理不会从它的名字去推断授权。
- 已有的未登记 `.synthesis-render-*` 和 `.synthesis-join-*` 目录保持不动。手动移除之前，请在应用停止的情况下检查已知路径；绝不要根据共享的文件名前缀去删除已保存的录音或恢复产物。
- 自动回收目前覆盖 Linux 上已知且未被修改的本地类别（custom、clone、design、LoRA 和 ensemble）。Windows/macOS、被覆写的提供方以及直接调用、不持租约的 Python 调用者保持它们正常的临时文件行为。它们目前还不具备所声称的硬崩溃回收资格。
- 出于保守，ensemble 登记要求普通的 custom、clone、design 和 LoRA 成员写入器都未被修改，即使某个被覆写的类别并不在这个 ensemble 里。否则它就保留普通的临时路径。一个参与机制的 ensemble 不能超过 1,024 个窗口的上限；它会拒绝，而不是用未登记的回退去绕过有界存储。
- ensemble 成员的暂存区和 Project 设计预览使用已登记的窗口工作区。Designer 页在 `designed_voices/previews` 下的预览仍然走单独的暂存路径，不受这个注册表覆盖。
- 不在参与机制的本地类别路径内的批处理行、直接的不持租约调用、`voicelines` 里的旧式暂存，以及分块编码器之外的章节导出/PCM 导出/合并，仍然在这个登记之外。已有的未登记父级文件会被保留；本次改动不授权按文件名清理历史文件。

警告会指出被保留的登记，或不可用的注册表授权。请保留那些路径和元数据用于诊断。应用不会重置损坏的注册表，不会递归清扫整个项目，也不会在参与机制的注册表满时退回到无人跟踪的溢出。
