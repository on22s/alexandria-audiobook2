# テイク履歴

Editor の Inspector で **Automatic take history** を開き、**Refresh setting** を選んでから **Turn on** をクリックします。このプロジェクト設定は既定でオフで、今後の再生成に適用されます。行を選択しなくても変更できます。

オンにすると、差し替えを生成または反映する前に、選択中の以前のテイクが保持されます。単語、話者、指示、テイク番号を編集しても、元に保存されたテイクのメタデータはそのままです。繰り返し編集しても、古い音声に新しい単語のラベルが付くことはありません。初回の生成にはアーカイブする以前のテイクがありません。

Inspector のスナップショット操作で、保存したテイクを試聴し、コピーを保護し、取り消し可能な削除を行い、確認後に完全に削除できます。プロジェクトのアーカイブ表示には、以前の本の生成も含まれます。試聴しても、スナップショットが現在の音声として選択されるわけではありません。

対応する Linux ホストでは、現在の本と行について公開の証拠が記録されたスナップショットに **Check & restore** が表示されます。使う前に、保留中の編集を保存してください。音声タスクは、元の入力、声と seed、モデル設定、発音、合成のウィンドウ、ネイティブ実行の依存関係、実際に保存されたバイトを検査します。検査でネイティブの声モデルが読み込まれることはありますが、新しい音声を合成することはありません。キャンセルを要求するには **Cancel audio task** を使い、タスクが終わるまで待ちます。

復元に成功すると、元のエンコード済みバイト、テイク番号、成果物のリビジョンが選択され、生成時の受領書も保持されます。置き換えられたテイクは、自動履歴がオフでも履歴に残ります。単語、話者、演技指示は書き換えません。依存関係が変わっていたり、証明が利用できなかったりすると拒否され、選択中のテイクは保持されます。古いスナップショット、別の本／行の識別情報、非対応のホストは引き続き試聴に使えます。保護されたスナップショットは復元できます。削除済みのスナップショットは、先に削除を取り消す必要があります。

アーカイブは 4,096 レコード、1 行あたり 16 件、音声の総量 1 GiB までです。削除済みや中断されたコピーも、完全に削除するまで件数に数えます。保留中の差し替えや、実行中のチャンク削除の取り消しでまだ必要なコピーは削除できません。受け入れに失敗した場合は、アーカイブの空きを増やすか、自動履歴をオフにしてから生成を再試行してください。オフでも既存のコピーは利用できます。明示的な復元には、置き換えられるテイクを保持するだけの空きが引き続き必要です。

生成がキャンセルされたり公開に失敗したりした場合、保持された以前のテイクは、差し替えが成功するまで保護されたままです。プロセスが中断した後は、不完全なアーカイブコピーが表示され、容量も消費したままになります。再試行の前に、そのコピーを明示的に削除してください。完了した保持コピーは、以前の作業用音声スロットが変わっていても、再試行時に再利用できます。壊れたポリシーは、設定を更新してオフにすれば置き換えられ、アーカイブを解析したり書き換えたりする必要はありません。

履歴を有効にしても、以前の編集で切り離された音声は復元できません。チャンクを再構築したり別の本を読み込んだりすると、新しい本／行の識別情報が作られます。自動保持は、そうした変更をまたいで保留中の行のメタデータを引き継ぎません。完了したアーカイブコピーは、プロジェクトのアーカイブから引き続き見つけられます。

スナップショットは、実際に保存されたバイトと記録された入力を保持します。スナップショットを取るだけでは、以前のレンダリングで使った正確な依存関係を証明することにはなりません。オーディオブックに使う前に、候補を聴いてください。

自動履歴を有効にすると、対象となる組み込みのローカル CustomVoice のレンダリングは、上限付きの公開受領書も記録します。これには現在、決定的な seed、内部の合成ウィンドウ、復旧に対応した配信の識別情報が必要です。観測された正確な発話入力は ASR とは独立に取得され、完成したエンコード済みファイルのハッシュとデコード後の形状に結び付けられます。選択した声／モデルの入力、発音の決定、ウィンドウのポリシー、本／行の識別情報、音声のリビジョンも結び付けられます。その他のレンダリングと以前のスナップショットは未証明のままです。既存のスナップショットが遡って認定されることはありません。受領書は復元の候補であり、明示的な操作で現在の依存関係と音声を検証する必要があります。

公開受領書と保留中の先行テイクのメタデータは、本ごとに 16 MiB の予算を共有します。各公開受領書は最大 4 KiB で、不変のアーカイブレコード／ペイロードの上限は引き続き適用されます。受領書の 64 MiB、モノラル／ステレオ、192 kHz、10 分という範囲の外にある有効な初回パスの音声は、証明なしで公開できます。新しい生成では、音声の選択と同時に以前の受領書をアトミックに置き換えるか、完全な証明が得られない場合はクリアします。履歴の閲覧は、モデルを読み込んだり、選択した音声をハッシュ化したり、発話の検証を実行したりしません。

## MPEG の検証とデコーダーの可用性

MPEG のスナップショットは、利用可能になる前に FFprobe と FFmpeg で個別に検査されます。デコーダーは、シーク可能なディスクリプター入力として受け入れ済みのオープンファイルを読み、PCM フレームの総数と形状を確認し、元の内容を再確認します。リサンプリング、正規化、アーカイブされた元データの置き換えは行いません。WAV、FLAC、OGG のスナップショットは既存の検証経路のままで、正規化範囲外の有限の float WAV サンプルも受け入れられます。

これには、シーク可能な `fd` 入力に対応した動作中の FFprobe と FFmpeg のビルドが必要です。欠けているか非対応の場合は、デコーダーのツールを更新してください。取得に失敗またはキャンセルした場合、保留中のコピーと容量の消費は残ります。再試行の前に、不完全なコピーを明示的に削除してください。選択中の現在のテイクは保持されます。

共有のデコーダーは、ステレオ MPEG の学習参照の変換も保護します。非公開のチェックポイントのステージングは、公開前に完全なモノラル変換を受け取り、元の参照は変わらないままです。デコーダーのタイムアウトは、所有するプロセスを停止して回収します。呼び出し元のファイル書き込みコールバックは、書き込みが終わるまで所有権を保ちます。ブロックされたファイルシステムの書き込みが、タイムアウト後に放置されることはありません。

## コンパクトなメタデータ

アーカイブの書き込みは、繰り返し現れるテキスト、生成の入力、来歴、合成ポリシーを、内容のハッシュで参照して一度だけ保存できます。コンパクト形式は、マニフェストのバイト数のうち少なくとも 4 KiB かつ 5% を節約できる場合にのみ使われます。元の受領書と選択した音声の意味は保たれます。同じレコード、音声、深さ、完全に展開した 16 MiB のマニフェストの上限が適用されます。これにより繰り返しのメタデータが減りますが、保存のたびにマニフェスト全体を検証して置き換えます。

既存の v1/v2 アーカイブは引き続き読めます。コンパクトなアーカイブは形式 v3 を使い、古いアプリケーションは書き換えを拒否します。古いアプリケーションに戻す前に、現在のアプリケーションでメタデータを展開してください。`app/` から、アプリケーションの Python 環境を有効にして実行します。

```sh
python -m audio_take_history /path/to/project-data --expand-metadata
python -m audio_take_history /path/to/project-data --compact-metadata
```

`take_history/` を含むデータディレクトリーを使ってください。どちらのコマンドもアーカイブのロックを保持し、既存の保留ファイル／アトミック置換の境界を使います。変換は、元の v1/v2 の書き込みフェンス、スナップショット、受領書、現在の音声の選択を保持します。後でアーカイブに書き込むと、展開したメタデータが再びコンパクト化されることがあります。参照先のペイロードが欠けている、変わっている、不正な場合は変換を拒否します。参照を手で編集せず、検査できるようアーカイブを保存しておいてください。スナップショットを削除すると、保持中、削除済み、不完全などのレコードからも使われなくなったペイロードだけが削除されます。
