## 3. Failures found in the machinery, and what was done

**FP8 arms measure nothing under `HF_HUB_OFFLINE=1`.** FP8 loads
`kernels-community/finegrained-fp8` **by version**, and version→revision
resolution goes through the Hub API, which offline mode blocks outright. The
local snapshot can never be recognised as "version 4" however completely it is
cached — an online fetch succeeds and the very next offline load still fails.
Two arms produced 766 rows, both arms 0 correct, 428 batches failed before a
token, and `meta.validation: "ok"`.
*Fixed:* `HF_HUB_OFFLINE=0` for FP8 arms only, plus a ten-second kernel
preflight in the wrapper. Failed artifacts are **kept** under their old tag.

**`$(date)` destroys `$?`.** `echo "[$(date -Is)] DONE $arm rc=$?"` prints
`rc=0` for a command that exited 1 — the substitution runs first and resets the
status. This is why DaisyMiller logged success while `generate_script.py`
called `sys.exit(1)` after chunk 12. **`set -e` would not have helped**; the
shell never saw a non-zero status. Four H100 wrappers fixed by rename; repo
lint added (repo was already clean).

**All-empty arms validated "ok".** The guard existed and was **opt-in**. Now
default-on, scoped to arms carrying a `predicted` key: 16 flagged of 729,
0 false positives (#448).

**Generation failures recorded the symptom, not the cause.** Diagnostics were
appended on the success path only. Now recorded before re-raise, plus a
preflight that refuses to evaluate a model that cannot generate (#449).

**Rows could not name their batch.** `prompt_sha256` was in the schema and
NULL in every row ever written. Now populated, and `--only-gold-ids` re-runs
only the windows carrying named rows (#451).

## 4. Open question that gates the rank/lr family

**The base model is not provably deterministic.** Two Qwen3-14B runs sharing a
base, a book and greedy decoding disagree on **3 of 133** base rows on
mushoku16 (00923, 00927 adjacent; 00352 apart — two batches):

```
mushoku16-00923  NANAHOSHI vs HITOGAMI
mushoku16-00927  NANAHOSHI vs HITOGAMI
mushoku16-00352  SYLPHY    vs NORN
```

On the pooled three-book set that is ~0.2 points of movement in the BASE. The
rank ladder reads differences of about that size, so **any rank or lr delta
below ~0.5 points may be unresolvable.** A probe is queued (§5). Hold further
rank and learning-rate variants until it reports.

Do not repeat this check by comparing `prompt_sha256` across old artifacts:
every value is NULL, so the comparison returns "identical" for every row and
means nothing.
