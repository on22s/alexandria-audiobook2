# Optional native packaging qualification

This crate is selected explicitly; app requirements, installers and default-off dispatch are unchanged. No wheel upload, publishing, release version bump, abi3, mandatory native dependency or automatic activation is included. PyO3/build-config stay exactly 0.27.2; Cargo.lock is unchanged. Maturin 1.15.0 and frontend tooling are version/hash pinned in build-tools.txt.

The narrow GitHub workflow builds an sdist, validates/extracts it, then builds a wheel from that archive with a fresh Cargo target and frozen/offline dependencies after explicit cargo fetch. It checks metadata/tags/RECORD and source provenance; installs into a clean disposable venv outside source/build trees; checks absent/default/requested behavior, actual native parity and policy invalidation, then uninstalls and verifies fallback. Build-tool provisioning is confined to hosted runners or explicitly approved isolated environments.

Eight standard hosted lanes: ubuntu-24.04 x64, windows-2022 x64, macos-15 arm64 and macos-15-intel x64, each CPython 3.10/3.12. Runner architectures are asserted. Each job has a 20-minute timeout, two jobs maximum in parallel and one Cargo worker. No secrets, write permissions, artifact uploads, paid/larger/self-hosted runners, cache publication, model downloads or app dependency installs. PR trigger paths are limited to this crate, speech-worker files and its workflow; manual dispatch is available. Only repository public code and synthetic fixtures run. Rust 1.96.0 is installed from the official rustup channel if needed. Pinned tool wheels come from PyPI; Cargo uses its locked registry graph.

Linux PEP517 passes explicit build arguments for manylinux_2_34 plus auditwheel check, because the Maturin hook otherwise defaults compatibility to off despite pyproject configuration; exact resulting tags are asserted. Linux audit requests manylinux_2_34; macOS deployment target is 11.0. These are artifact target/audit checks, not proof of execution on glibc 2.34, Windows 10 or macOS 11. New hosted OS runs cannot establish those floors. Native DLL/Mach-O dependency qualification, actual minimum-OS runs, actual free-threaded source/runtime/race checks, sustained native allocation/exhaustion and full-app/audio quality remain open. Build.rs and loader reject unsupported/free-threaded runtimes; this workflow does not exercise a real free-threaded interpreter.

No distinct approved older/newer version exists here: genuine upgrade remains UNRUN. Clean installation/uninstallation of 0.1.0 does not satisfy upgrade qualification. CPython 3.10 is a legacy compatibility lane; no live interpreter upgrade is included. CPython 3.11 and >=3.13, PyPy, Linux ARM/musl and Windows ARM wheels are outside this scope.

Local Linux gates can establish the actual source -> sdist -> wheel and clean-runtime chain for existing 3.10/3.12 interpreters; Windows/macOS results remain unrun until the workflow is approved and executed. Publishing this optional packaging change does not publish wheels, establish OS-floor qualification or activate the native backend.
